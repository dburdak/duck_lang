2. Англійські каламбури та птице-терміни
Замість нудних системних слів можна використати англійські каламбури для синтаксису, операторів та помилок:
Деларація та зв'язування:
drake замість let / const (селезень утримує значення).
duck замість fn / def.
ducking — каррування (currying) або часткове застосування функції.
Керування потоком та типи:
peck або waddle_if замість if.
im-peck-able — значення true або метод assert.
duck_type — оператор перевірки типу (typeof).
Модулі та пайплайни:
breadcrumbs (~>) — пайплайн-оператор для передачі даних між функціями (качка іде по крихтах).
migration — оператор import / export для підключення інших файлів.
Системні помилки:
QuackOverflowError — помилка переповнення стеку при нескінченній рекурсії.
LameDuckException — помилка типу або неочікуваний null.
3. Приклади коду
Обчислення факторіалу (Рекурсія + Групування)
# Визначення функції factorial
drake factorial (duck [n]
  (peck (= n 0)
    1
    (* n (waddle (- n 1)))))  # waddle здійснює рекурсивний виклик

# Виклики та друк
quack (factorial 5)  # Виведе 120


Обробка списків через дзьоб і хвіст (beak & tail)
Функція sum, яка рекурсивно сумує всі елементи гнізда:
drake sum (duck [nest_of_numbers]
  (peck (empty? nest_of_numbers)
    0
    (+ (beak nest_of_numbers) 
       (waddle (tail nest_of_numbers)))))

quack (sum [10 20 30 40])  # Повертає 100


Каскадний пайплайн через хлібні крихти (~>)
drake double (duck [x] (* x 2))
drake add_five (duck [x] (+ x 5))

# Передаємо 10 через ланцюжок функцій
10 ~> double ~> add_five ~> quack  # Виведе 25


4. Ще більш радикальний варіант: Duck Combinators
Якщо хочеться зробити мову концептуально мінімалістичною (на зразок SKI-комбінаторного числення), можна створити мову, де взагалі немає змінних, а є лише три качки-комбінатори:
Mallard (I-комбінатор): Повертає те, що отримав (Mallard x) => x.
Drake (K-комбінатор): Повертає першу качку і ігнорує другу (Drake x y) => x.
Goose (S-комбінатор): Передає аргументи далі (Goose x y z) => (x z (y z)).
З комбінації цих трьох качок можна вибудувати будь-яку обчислювану функцію, арифметику Черча та рекурсію без жодного if чи while.

Чернетка EBNF для grammar.ebnf (Task 2)
Оскільки рекурсивний спуск (Recursive Descent Parser) вимагає чітких правил граматики без лівої рекурсії, EBNF для цієї мови буде виглядати так:
Program         ::= Statement* ;

Statement       ::= VarDeclStmt
                  | AssignStmt
                  | IfStmt ;

VarDeclStmt     ::= ("hatch" | "egg") IDENTIFIER ":" Type "=" Expression ";" ;
AssignStmt      ::= IDENTIFIER "=" Expression ";" ;

IfStmt          ::= "peck" Expression "{" Statement+ "}" [ "flap" "{" Statement+ "}" ] ;

Type            ::= "duck32" | "duck64" | "pond_bool" ;

Expression      ::= EqualityExpr ;
EqualityExpr    ::= AddExpr { ("==" | "!=") AddExpr } ;
AddExpr         ::= PrimaryExpr { ("+" | "-") PrimaryExpr } ;
PrimaryExpr     ::= IDENTIFIER | INT_LITERAL | "quack" | "silence" | "(" Expression ")" ;


Чому такий підхід ідеально підходить для Stage 1?
Легко побудувати AST Hierarchy (Task 4):
StmtNode → VarDeclNode, AssignNode, IfNode
ExprNode → BinaryOpNode, LiteralNode, VarRefNode
Зручно реалізувати ручний лексер (Task 4): Скінченний автомат за байтами простіше відлагоджувати, коли є чіткі токени (IDENTIFIER, NUMBER, PECK, FLAP, LBRACE, RBRACE).
Емоджі чудово покривають вимогу креативності: Якщо оберете варіант з емоджі (наприклад, 🦆 замість peck), ваш лексер читатиме послідовність байтів 0xF0 0x9F 0xA6 0x86 як один токен TOKEN_IF.

Як влаштований 4-байтовий UTF-8 автомат
Майже всі сучасні емоджі належать до діапазону U+10000..U+10FFFF, тому в UTF-8 вони завжди кодуються 4 байтами:
Байт 1: 0xF0 (11110000 в двійковій) — сигналізує лексеру, що це початок 4-байтового UTF-8 символу.
Байт 2: 0x9F або 0x8F..0xBF (10xxxxxx) — продовження.
Байт 3: 0x80..0xBF (10xxxxxx) — продовження.
Байт 4: 0x80..0xBF (10xxxxxx) — фінальний байт.
Як швидко дізнатися байти будь-якого емоджі
Якщо ви захочете додати інші емоджі у граматику, їхні байти можна миттєво отримати через короткий Python-скрипт під час розробки лексера:
emoji = "🦆"
utf8_bytes = emoji.encode("utf-8")

print("Hex:", " ".join(f"0x{b:02X}" for b in utf8_bytes))
print("Dec:", " ".join(str(b) for b in utf8_bytes))
# Виведе:
# Hex: 0xF0 0x9F 0xA6 0x86
# Dec: 240 159 166 134

Усі наведені фічі зберігають синтаксис LL(1) (зручно для рекурсивного спуску) та генерують простий код в LLVM IR чи C:

Синтаксис: quack expr; або 🔊 expr;
Чому це просто для парсера й AST: Окремий PrintStmtNode(expr).
Чому це просто для кодогенератора: На етапі кодогенерації в LLVM IR це просто виклик стандартного printf("%d\n", val) або puts().
waddle / 🔁 (Цикл While)
Синтаксис: waddle (condExpr) { stmt+ }
Чому це просто для парсера й AST: WhileStmtNode(condition, body). Структура парсингу нічим не відрізняється від вашого if.
Чому це просто для кодогенератора: В LLVM IR це стандартні 3 базові блоки: loop.cond, loop.body, loop.merge з умовним переходом br.

def parse_program(self):
    stmts = []
    exit_node = None

    while self.peek_line() is not None:
        self.next_line()
        tok = self.peek()

        if tok is not None and tok.kind == "statement" and tok.text in ("exit", "finish"):
            exit_node = self.parse_exit()
            self.expect_eol()
            # Якщо ПІСЛЯ кінцевого exit на верхньому рівні є ще щось — це помилка 6
            if self.peek_line() is not None:
                nxt = self.peek_line()
                raise_err(6, nxt[0].line, nxt[0].col)
            break
        else:
            stmt_node = self.parse_statement()
            stmts.append(stmt_node)
            if not isinstance(stmt_node, (IfNode, WhileNode)):
                self.expect_eol()

    if exit_node is None:
        err_line = self.lines[-1][-1].line if (self.lines and self.lines[-1]) else 1
        raise_err(5, err_line, 1)

    first_line = stmts[0].line if stmts else exit_node.line
    first_col  = stmts[0].col  if stmts else exit_node.col
    return ProgramNode(first_line, first_col, stmts, exit_node)

def visit_program(self, node):
    for stmt in node.stmts:
        stmt.accept(self)

    # Генеруємо кінцевий exit тільки якщо поточний блок LLVM ще не терміновано (не було ret)
    if node.exit and not self.builder.block.is_terminated:
        node.exit.accept(self)

    if not self.builder.block.is_terminated:
        self.builder.unreachable()
